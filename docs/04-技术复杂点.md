# 04-技术复杂点

## 1. 自动配置边界

- 必须支持启用和关闭。
- 必须允许消费方 Bean 覆盖默认 Bean。
- 缺少依赖时不得误装配。
- starter 不得强制启用所有模块。

## 2. 上下文传播

需要统一处理：

- Trace。
- Tenant。
- Principal。
- Locale。
- Audit metadata。

传播场景：

- HTTP。
- MQ。
- Task。
- Async。
- Remote call。

## 3. 并发控制

复杂点：

- Redis Lua 原子性。
- 可重入锁释放安全。
- 幂等状态机。
- 限流窗口精度。
- 重试和熔断组合。

## 4. 数据访问兼容

复杂点：

- MyBatis-Plus 插件顺序。
- 多数据源上下文清理。
- 数据库方言差异。
- Flyway migration 兼容。
- 租户和数据权限拦截顺序。

## 5. 微服务韧性

复杂点：

- 服务发现不可用。
- 远程调用超时。
- 重试放大流量。
- 熔断误伤。
- 降级结果不能由框架替业务决定。

## 6. 注释要求

公共 API、SPI、自动配置、复杂算法和风险边界必须有必要注释或 Javadoc。注释说明原因、边界和风险，不重复代码。
