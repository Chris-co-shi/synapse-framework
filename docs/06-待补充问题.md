# 06-待补充问题

## 1. 一阶段已关闭的问题

以下问题在一阶段已经形成结论：

- `synapse-web` 一阶段只保留 Servlet MVC，不再混入 WebFlux。
- Gateway / WebFlux 后续单独建模块，不放入 `synapse-web`。
- `synapse-security` 不引入 Spring Security Web / SecurityFilterChain / MethodSecurity。
- trusted-header、PermissionChecker、`@RequirePermission` 已作为一阶段安全基础闭环。
- `SynapseAuthenticationException`、`SynapseAccessDeniedException` 已下沉到 core。
- security 场景细分错误码保留在 `synapse-security`。
- message 只做契约，不做 MQ SDK、渠道 SDK、DB Repository。
- file 一阶段只做存储抽象和本地轻量实现，不做文件中心。
- cache 一阶段只做缓存、锁、限流、幂等基础设施。

## 2. 二阶段候选问题

以下问题留给二阶段或后续平台服务讨论。

### 2.1 Gateway / WebFlux

- 是否新增 `synapse-gateway` 模块。
- Gateway 是否负责 trusted-header 注入。
- Gateway 是否负责统一鉴权前置逻辑。
- Gateway 的异常响应是否复用 `synapse-web` 的 Result 契约，还是提供独立 reactive 响应契约。

### 2.2 Tenant / Data Permission

- 是否恢复 `synapse-tenant` 进入 reactor。
- 是否恢复 `synapse-data-permission` 进入 reactor。
- 租户上下文是否复用 `OperationContext`。
- DataScope / ABAC 是否由独立模块实现。
- 多表 join 场景的数据权限字段冲突如何处理。

### 2.3 Task / Async

- 是否新增 `synapse-task`。
- 定时任务、异步任务、MQ 消费场景如何统一建立 `OperationContext`。
- 默认 system actor 是否允许，还是必须显式指定 actor。
- 任务失败后的审计和追踪如何记录。

### 2.4 Message Runtime

一阶段 `synapse-mq` 只做契约。后续需要讨论：

- 是否提供 RocketMQ / Kafka / RabbitMQ adapter。
- 是否提供 outbox / reliable message 运行时。
- 是否提供死信、补偿、重试的默认实现。
- 是否进入平台消息中心，而不是 framework。

### 2.5 File Platform

一阶段 `synapse-file` 只做基础存储抽象。后续需要讨论：

- 文件中心是否作为 platform service。
- 是否需要附件表。
- 是否需要文件权限。
- 是否支持预览、转码、OCR、水印。
- 是否支持 MinIO / OSS / S3 adapter。

### 2.6 Cloud / Remote Call

- 是否新增 `synapse-cloud`。
- OpenFeign / LoadBalancer / Resilience4j 是否作为独立 adapter。
- 远程调用上下文传播是否复用 `OperationContextSnapshot`。
- 服务间鉴权是否与 trusted-header 统一。

## 3. 版本与发布问题

- Spring Boot 3.5.x 后续补丁版本跟进策略。
- Spring Cloud / Spring Cloud Alibaba 是否进入二阶段。
- Seata / RocketMQ / Nacos 是否作为 platform 层依赖，而不是 framework 一阶段依赖。
- GitHub Packages / Maven Central 发布策略。
- 是否区分 internal BOM 与 public BOM。

## 4. 工程治理问题

- 是否补充模块级 Skill 文档。
- 是否补充自动生成 API 文档。
- 是否引入依赖边界检查脚本。
- 是否将 `mvn clean test`、`mvn validate`、边界搜索固化为 CI。
- 历史保留目录是否在二阶段前归档或删除。

## 5. 不应再反复讨论的问题

除非项目阶段变化，以下结论保持冻结：

- 一阶段不做业务 Controller。
- 一阶段不做业务 Entity / Mapper / migration。
- 一阶段不做 starter。
- 一阶段不做 Gateway / WebFlux。
- 一阶段不做平台文件中心、消息中心、任务中心。
- 一阶段不做 ABAC / DataScope。
- 一阶段不做多租户。
