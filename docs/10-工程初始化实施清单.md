# 26-工程初始化实施清单

## 1. 开发前检查

每次开发前必须确认：

- [ ] 已读取 `AGENTS.md`。
- [ ] 已确认本次任务属于 framework、platform service 还是 business application。
- [ ] 已确认本次任务是否属于一阶段 10 个 reactor 模块。
- [ ] 已确认是否会新增依赖。
- [ ] 已确认是否会影响模块边界。
- [ ] 已确认是否需要修改自动配置。
- [ ] 已确认是否需要新增测试。

## 2. 一阶段模块检查

一阶段允许修改的 reactor 模块：

- [ ] `synapse-bom`
- [ ] `synapse-core`
- [ ] `synapse-web`
- [ ] `synapse-data`
- [ ] `synapse-cache`
- [ ] `synapse-security`
- [ ] `synapse-oauth2`
- [ ] `synapse-audit`
- [ ] `synapse-file`
- [ ] `synapse-mq`

一阶段不应恢复：

- [ ] `synapse-task`
- [ ] `synapse-tenant`
- [ ] `synapse-data-permission`
- [ ] `synapse-cloud`
- [ ] `starter`
- [ ] `gateway / webflux`

## 3. 模块新增或调整检查

如果新增或调整模块，必须确认：

- [ ] 是否加入 Maven reactor。
- [ ] 是否加入 BOM 管理。
- [ ] 是否有清晰模块定位。
- [ ] 是否存在反向依赖。
- [ ] 是否出现业务概念。
- [ ] 是否可以通过 SPI / Port 交给消费方实现。
- [ ] 是否存在自动配置。
- [ ] 自动配置是否可被用户 Bean 覆盖。
- [ ] 自动配置是否有条件装配。
- [ ] 外部连接是否不会在默认情况下强制触发。

## 4. 禁止项检查

生产代码不得新增：

- [ ] 业务 Controller。
- [ ] 业务 Entity。
- [ ] 业务 Mapper。
- [ ] 业务 Repository。
- [ ] 业务 migration。
- [ ] 生产启动类。
- [ ] 前端页面。
- [ ] 示例业务应用。
- [ ] 平台服务实现。
- [ ] WebFlux / Gateway 到 `synapse-web`。
- [ ] Spring Security Web / SecurityFilterChain 到 `synapse-security`。
- [ ] 真实 MQ / 渠道 SDK 到 `synapse-mq`。
- [ ] 上传下载 API / 附件表到 `synapse-file`。
- [ ] 业务缓存 key 到 `synapse-cache`。

## 5. 自动配置检查

自动配置必须满足：

- [ ] `AutoConfiguration.imports` 已注册。
- [ ] 公共配置类有必要 Javadoc。
- [ ] 默认 Bean 使用 `@ConditionalOnMissingBean`。
- [ ] 可选能力使用 `@ConditionalOnProperty` 或 `@ConditionalOnClass`。
- [ ] 不覆盖消费方自定义 Bean。
- [ ] 不强制连接外部 Redis、MQ、DB、OSS 等资源。
- [ ] Filter 顺序有明确说明。
- [ ] AOP 适配不会覆盖消费方已有代理配置。

## 6. 测试检查

需要根据模块能力补充测试：

- [ ] 自动配置测试。
- [ ] 属性绑定测试。
- [ ] 用户 Bean 覆盖测试。
- [ ] 缺少依赖不误装配测试。
- [ ] 错误码和异常语义测试。
- [ ] 上下文传播测试。
- [ ] Filter / AOP 顺序测试。
- [ ] 并发、锁、限流、幂等测试。
- [ ] 测试样例不包含无关业务语义。

## 7. 文档检查

文档必须满足：

- [ ] 使用中文。
- [ ] 描述当前代码事实，而不是过期规划。
- [ ] 明确模块边界。
- [ ] 明确不做什么。
- [ ] 不放个人面试表达、求职表达或与项目无关内容。
- [ ] 不把平台服务职责写成 framework 一阶段职责。

## 8. 完成检查

任务完成前必须执行：

```bash
/Users/sxc/Documents/tool/apache-maven-3.9.0/bin/mvn -q clean test
/Users/sxc/Documents/tool/apache-maven-3.9.0/bin/mvn -q validate
git diff --check
```

如果因为 Docker / Testcontainers 等本地环境导致容器测试跳过或失败，必须说明原因。


```bash

```

```bash

```

```bash
rg -n "Controller|RestController|RequestMapping|GetMapping|PostMapping|Entity|TableName|BaseMapper|Repository|JdbcTemplate|DataSource|java.sql|mybatis|MyBatis" synapse-cache synapse-file
```

```bash
rg -n "order|inventory|stock|workflow|approval|employee|customer|supplier|product|material|warehouse|avatar|attachment" */src/main/java */src/test/java
```

合理命中需要说明原因，不要无脑删除。例如 security 模块中的 role / permission 是安全抽象，不是业务污染。
