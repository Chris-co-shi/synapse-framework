# 01-项目定位与边界

## 1. 项目定位

Synapse Framework 是面向 Java 企业级业务系统的通用技术基座。

本仓库只沉淀可复用的框架能力、技术契约、自动配置、SPI、Port、轻量 Adapter、上下文传播机制和测试约束，供业务系统按需引入。

本仓库不是业务平台，也不是后台管理系统。

## 2. 本仓库不做什么

Synapse Framework 不承载以下内容：

- 不做业务启动应用。
- 不做后台管理端。
- 不做前端页面。
- 不做 IAM / RBAC / 用户中心业务系统。
- 不做订单、库存、流程、工单、客户、供应商等业务域模型。
- 不做业务 Controller。
- 不做业务 Entity / Mapper / migration。
- 不做平台文件中心、消息中心、任务中心、集成中心。
- 不做 Gateway / WebFlux，一阶段只保留 Servlet MVC Web 基础能力。

业务系统可以依赖本框架，但本框架不得反向依赖业务系统。

## 3. 一阶段已封板模块

一阶段只保留以下 10 个模块进入 Maven reactor：

```text
synapse-bom
synapse-core
synapse-web
synapse-data
synapse-cache
synapse-security
synapse-oauth2
synapse-audit
synapse-file
synapse-mq
```

一阶段不纳入：

```text
synapse-task
synapse-tenant
synapse-data-permission
synapse-cloud
starter
gateway / webflux
platform service
```

历史目录可以暂时保留，但不得进入一阶段 reactor，也不得被一阶段模块依赖。

## 4. 一阶段核心目标

一阶段目标不是做大功能，而是把技术基座最小闭环跑通：

- 统一核心错误码、异常、ID、OperationContext。
- 统一 Servlet MVC 响应、异常处理、Filter 阶段异常桥接。
- 建立 data 自动填充与 OperationContext 的关系。
- 建立 trusted-header、AuthenticatedUser、PermissionChecker、`@RequirePermission` 的安全基础链路。
- 将 OAuth2 / JWT / JWK 能力收敛到 `synapse-oauth2`。
- 将审计收敛为事件契约，不直接落库。
- 将 mq 收敛为消息外壳、上下文传播、发布/消费 SPI 契约。
- 将 cache 收敛为缓存、锁、限流、幂等基础设施。
- 将 file 收敛为文件存储基础抽象和本地轻量实现。

## 5. 消费方关系

```text
Business Application
  -> depends on Synapse Framework
  -> owns startup class
  -> owns business model
  -> owns API
  -> owns database schema
  -> owns business permission codes

Synapse Framework
  -> provides reusable technical foundation
  -> provides contracts and auto-configuration
  -> never depends on business application
```

## 6. 成功标准

一阶段封板标准：

- 根 reactor 只包含一阶段 10 个模块。
- 全量 `mvn clean test` 通过。
- `mvn validate` 通过。
- `git diff --check` 通过。
- 模块之间无不合理反向依赖。
- `synapse-web` 无 WebFlux / Gateway 残留。
- `synapse-security` 不引入 Spring Security Web / SecurityFilterChain / MethodSecurity。
- `synapse-mq` 不包含真实 MQ、DB、外部渠道 SDK 实现。
- `synapse-cache` 不包含业务 key / 业务规则。
- `synapse-file` 不包含文件中心、上传下载 API、附件表、文件权限业务。
- 文档描述与当前代码边界一致。
