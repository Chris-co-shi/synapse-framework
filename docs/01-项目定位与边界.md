# 01-项目定位与边界

## 1. 项目定位

Synapse Framework 是面向 Java 企业应用的通用技术底座。

本仓库只沉淀可复用的技术模块、架构抽象、自动配置、SPI、Adapter、测试规范和 AI 协作规则，供其他项目作为依赖集成。

本仓库不是：

- 后台管理系统。
- IAM/Auth/RBAC 业务系统。
- 业务应用。
- 脚手架启动应用。
- Admin UI 或前端项目。

## 2. 核心目标

- 统一 Web、Data、Cache、Security、Audit、Tenant、Data Permission、Message、File、Task、Cloud、Starter 等技术能力。
- 提供跨项目一致的异常、响应、Trace、审计、租户、幂等、限流、远程调用和韧性治理基础设施。
- 通过文档和 Skill 固化工程规则，降低 AI Agent 长期协作产生的风格漂移。

## 3. 第一阶段边界

第一阶段只做技术底座最小闭环：

- 技术模块。
- 自动配置。
- SPI / Port。
- Adapter。
- 测试支撑。
- 文档和 Skill。

第一阶段不做：

- 业务 Controller。
- 业务 Entity / Mapper / migration。
- 业务启动类。
- 示例应用。
- 前端页面。
- 业务模块脚手架。

## 4. 消费方关系

```text
Business Application
  -> depends on Synapse Framework
  -> owns startup class
  -> owns business model
  -> owns API and database schema

Synapse Framework
  -> provides reusable technical foundation
  -> never depends on business application
```

## 5. 成功标准

- 模块边界清晰。
- 无业务代码。
- 无启动应用。
- 技术能力可被消费方按需启用。
- 公共 API、SPI、自动配置和复杂逻辑有必要注释。
- 每个完成模块有对应 Skill。
