# 01-项目定位与边界

## 1. 项目定位

Synapse Framework 是面向 Java 企业级业务系统的通用技术基座。

本仓库只沉淀可复用的框架能力、技术契约、自动配置、SPI、Port、轻量 Adapter、上下文传播机制和测试约束，供业务系统或 Platform 服务按需引入。

本仓库不是业务平台，也不是后台管理系统。

## 2. 本仓库不做什么

Synapse Framework 不承载以下内容：

- 不做业务启动应用。
- 不做后台管理端。
- 不做前端页面。
- 不做 IAM / RBAC / 用户中心业务系统。
- 不做订单、库存、流程、工单、客户、供应商等业务域模型。
- 不做业务 Controller。
- 不做业务 Entity / Mapper / migration。
- 不做平台文件中心、消息中心、集成中心。
- 不做 Gateway 可启动服务；WebFlux 只作为 `synapse-webflux` 技术支撑模块存在。
- 不做用户、角色、权限身份 Header 恢复协议。

业务系统可以依赖本框架，但本框架不得反向依赖业务系统。

## 4. 当前核心目标

Framework 的目标不是堆叠平台功能，而是形成稳定的技术基座：

- 统一核心错误码、异常、ID、OperationContext。
- 统一 Servlet MVC 与 WebFlux 的响应、异常和上下文技术支撑，同时保持执行模型隔离。
- 建立 data 自动填充与 OperationContext 的关系。
- 建立 Web 无关的 `AuthenticatedPrincipal`、CurrentPrincipalContext、PermissionChecker 和权限注解能力。
- 通过独立 OAuth2 Resource Server 模块验证 Bearer Token 并建立安全主体。
- 将 Authorization Server 侧能力限制为 JWT 签发和密钥技术支撑，不实现 IAM 业务。
- 将审计收敛为事件契约，不直接提供审计中心。
- 将 mq 收敛为消息外壳、上下文传播、发布/消费 SPI 契约。
- 将 cache 收敛为缓存、锁、限流、幂等基础设施。
- 文件能力不进入 Framework，由 Synapse Platform 的可启动文件服务承载。
- 建立供应商中立的 observability 与 resilience 技术边界。

## 5. 身份认证原则

```text
Client Bearer Token
  -> Gateway optional validation
  -> downstream Resource Server independent validation
  -> AuthenticatedUser / AuthenticatedClient
  -> Synapse CurrentPrincipalContext
  -> OperationContext / PermissionChecker
```

固定约束：

- Gateway 与下游只传播 Bearer Token。
- 下游服务独立验证签名、issuer、audience、有效期和 token contract。
- 用户、角色、权限 Header 不作为可信身份来源。
- `synapse-security` 不负责解析或验证 Token。

## 6. 消费方关系

```text
Business Application / Synapse Platform Service
  -> depends on Synapse Framework
  -> owns startup class
  -> owns business or platform model
  -> owns API
  -> owns database schema
  -> owns permission codes

Synapse Framework
  -> provides reusable technical foundation
  -> provides contracts and auto-configuration
  -> never depends on business application
```

## 7. 成功标准

当前封板标准：

- 根 reactor 只包含已确认技术模块。
- 全量 `mvn clean test` 通过。
- `mvn validate` 通过。
- `git diff --check` 通过。
- 模块之间无不合理反向依赖。
- `synapse-webmvc` 无 WebFlux / Gateway / OAuth2 Resource Server 残留。
- `synapse-webflux` 无 Servlet MVC / Gateway 服务 / OAuth2 Resource Server 残留。
- `synapse-security` 不引入 Spring Security Web / SecurityFilterChain / MethodSecurity，不包含身份 Header 认证协议。
- OAuth2 Resource Server 模块不包含私钥签发能力。
- `synapse-messaging` 不包含真实 MQ、DB、外部渠道 SDK 实现。
- `synapse-cache` 不包含业务 key / 业务规则。
- Framework 不包含文件存储模块或文件服务实现。
- 文档描述与当前代码边界一致。
