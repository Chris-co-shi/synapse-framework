# 03-核心链路设计

## 1. OperationContext 链路

`OperationContext` 是 Framework 最核心的上下文根。

```text
HTTP / MQ / Job / Async / Internal Call
  -> OperationContext restore / create
  -> OperationActor
  -> traceId / requestId / source
  -> data / audit / mq / security 使用
```

Framework 不把“当前用户”绑定死在 Web Controller，也不把当前登录人直接放在 data 模块中。

通用规则：

- `core` 定义 `OperationContext`。
- `security` 将 `AuthenticatedUser` / `AuthenticatedClient` 适配为 `OperationActor`。
- `data` 通过 `OperationContextProvider` 获取创建人、更新人等自动填充信息。
- `audit` 通过 `OperationContext` 获取操作者、来源和追踪信息。
- `mq` 通过消息头传播 `OperationContextSnapshot`。

## 2. Servlet MVC OAuth2 请求链路

```text
HTTP Request
  -> Authorization: Bearer <token>
  -> Spring Security BearerTokenAuthenticationFilter
  -> JwtDecoder / validators
  -> SynapseJwtAuthenticationConverter
  -> SynapseJwtPrincipalMapper
  -> SynapseJwtAuthenticationToken
  -> Spring SecurityContextHolder
  -> SynapseSecurityContextBridgeFilter
  -> Synapse SecurityContext + OperationContext
  -> Consumer Controller / Service
  -> PermissionChecker
  -> HTTP Response
  -> Scope close
```

说明：

- Token 必须完成签名、issuer、audience、有效期及 Synapse claim contract 校验。
- Gateway 可以执行入口验证，但下游服务仍必须独立验证 Token。
- Gateway 与下游之间只传播 Bearer Token，不传播可直接信任的用户、角色或权限 Header。
- `SynapseExceptionBridgeFilter` 负责普通 Servlet Filter 阶段的 Framework 异常桥接。
- `GlobalExceptionHandler` 处理进入 MVC 后的异常。
- Resource Server 的 401/403 由专用 entry point 和 access denied handler 写出。
- `synapse-webmvc` 只提供通用 Servlet MVC 能力，不承载 OAuth2 Resource Server。

## 3. Reactive OAuth2 请求链路

```text
HTTP Request
  -> Authorization: Bearer <token>
  -> Reactive Resource Server
  -> ReactiveJwtDecoder / validators
  -> SynapseReactiveJwtAuthenticationConverter
  -> AuthenticatedUser / AuthenticatedClient
  -> Spring Reactive SecurityContext
  -> Synapse Reactive SecurityContext / OperationContext
  -> Handler / Service
```

WebFlux 使用 Reactor Context，不能把 Servlet ThreadLocal 作为唯一上下文来源。

## 4. 权限检查链路

```text
Consumer Service Method
  -> @RequirePermission
  -> RequirePermissionAspect
  -> PermissionChecker.require(permission)
  -> AuthenticatedPrincipal permissions snapshot
```

同时支持显式调用：

```text
MQ / Job / Async / Internal Use Case
  -> PermissionChecker.require(permission)
```

AOP 只是声明式适配，不是唯一安全边界。

## 5. Data 自动填充链路

```text
Consumer Data Operation
  -> MyBatis-Plus MetaObjectHandler
  -> OperationContextProvider
  -> OperationActor
  -> createdBy / updatedBy / trace metadata
```

`data` 不依赖 `security`，因此异步、MQ、Job 场景也可以通过 `OperationContext` 显式恢复操作者。

## 6. MQ 上下文传播链路

```text
Producer
  -> MessagePublishTemplate
  -> OperationContextProvider
  -> OperationContextSnapshot
  -> MessageEnvelope.headers
  -> MessagePublisher SPI
  -> Broker / Transport
  -> Consumer
  -> MessageConsumeTemplate
  -> OperationContext restore
  -> MessageHandler
  -> MessageExceptionClassifier
  -> SUCCESS / RETRY / DISCARD
```

MQ Header 只传播可追踪的操作上下文，不传播 Bearer Token、roles 或 permissions。

`synapse-messaging` 只定义契约，不直接绑定 RocketMQ / Kafka / RabbitMQ SDK。具体 ACK、重试、丢弃或死信由 MQ 适配器根据 `MessageConsumeResult` 转换。

## 7. Cache 并发链路

```text
Consumer Use Case
  -> CacheKey / IdempotencyKey / LockKey
  -> CacheClient / Lock / RateLimiter / IdempotencyGuard
  -> Redis / Caffeine
```

缓存 key、幂等 key、锁粒度、限流维度必须由消费方决定。

## 8. Audit 链路

```text
Technical Event
  -> Audit Event Model
  -> Audit Publisher / Port
  -> Consumer Adapter
```

审计事件结构属于 Framework，审计落库、查询和管理后台属于消费方或 Platform 服务。
