# 03-核心链路设计

## 1. OperationContext 链路

`OperationContext` 是一阶段最核心的上下文根。

```text
HTTP / MQ / Task / Async / Internal Call
  -> OperationContext restore / create
  -> OperationActor
  -> traceId / requestId / source
  -> data / audit / mq / security 使用
```

一阶段不把“当前用户”绑定死在 Web Controller，也不把当前登录人直接放在 data 模块中。

通用规则：

- `core` 定义 `OperationContext`。
- `security` 将 `AuthenticatedUser` 适配为 `OperationActor`。
- `data` 通过 `OperationContextProvider` 获取创建人、更新人等自动填充信息。
- `audit` 通过 `OperationContext` 获取操作者、来源和追踪信息。
- `mq` 通过消息头传播 `OperationContextSnapshot`。

## 2. Servlet MVC Web 请求链路

```text
HTTP Request
  -> SynapseExceptionBridgeFilter
  -> Trace / Context Filter
  -> TrustedHeaderAuthenticationFilter
  -> Consumer Controller
  -> GlobalExceptionHandler
  -> Result
  -> HTTP Response
```

说明：

- `SynapseExceptionBridgeFilter` 处理 Filter 阶段抛出的 `SynapseException`。
- `GlobalExceptionHandler` 处理进入 MVC 后的异常。
- `WebExceptionResponseFactory` 负责异常到 HTTP 状态码和 `Result` 响应体的转换。
- `synapse-webmvc` 只保留 Servlet MVC 能力，不处理 WebFlux / Gateway。

## 3. trusted-header 安全链路

```text
Gateway / Trusted Caller
  -> X-Synapse-* Headers
  -> timestamp validation
  -> HMAC signature validation
  -> TrustedHeaderAuthenticatedUserResolver
  -> SecurityContext
  -> OperationContext
```

一阶段安全模块只负责可信请求头恢复和权限检查基础能力。

不做：

- 用户登录。
- 用户中心。
- 角色授权后台。
- Spring Security FilterChain。
- MethodSecurity。
- ABAC / DataScope。

## 4. 权限检查链路

```text
Consumer Service Method
  -> @RequirePermission
  -> RequirePermissionAspect
  -> PermissionChecker.require(permission)
  -> AuthenticatedUser permissions
```

同时支持显式调用：

```text
MQ / Task / Async / Internal Use Case
  -> PermissionChecker.require(permission)
```

AOP 只是声明式适配，不是唯一安全边界。

## 5. Data 自动填充链路

```text
Consumer Data Operation
  -> MyBatis-Plus MetaObjectHandler
  -> OperationContextProvider
  -> OperationActor
  -> createdBy / updatedBy / trace metadata
```

`data` 不依赖 `security`，因此异步、MQ、任务场景也可以通过 `OperationContext` 显式恢复操作者。

## 6. MQ 上下文传播链路

```text
Producer
  -> MessagePublishTemplate
  -> OperationContextProvider
  -> OperationContextSnapshot
  -> MessageEnvelope.headers
  -> MessagePublisher SPI
  -> Broker / Transport
  -> Consumer
  -> MessageConsumeTemplate
  -> OperationContext restore
  -> MessageHandler
  -> MessageExceptionClassifier
  -> SUCCESS / RETRY / DISCARD
```

mq 模块只定义契约，不直接绑定 RocketMQ / Kafka / RabbitMQ SDK。
具体 ACK、重试、丢弃或死信由未来 MQ 适配器根据 `MessageConsumeResult` 转换。
MQ framework 层异常通过 `MessageException.retryable()` 表达是否建议重试，不承载业务失败语义。

## 7. Cache 并发链路

```text
Consumer Use Case
  -> CacheKey / IdempotencyKey / LockKey
  -> CacheClient / Lock / RateLimiter / IdempotencyGuard
  -> Redis / Caffeine
```

缓存 key、幂等 key、锁粒度、限流维度必须由消费方决定。

## 8. File 存储链路

```text
Consumer Use Case
  -> StoreFileCommand
  -> FileStorage
  -> LocalFileStorage / future ObjectStorage Adapter
  -> StoredFile
```

文件模块不暴露上传下载接口，不做附件表和文件权限。

## 9. Audit 链路

```text
Technical Event
  -> Audit Event Model
  -> Audit Publisher / Port
  -> Consumer Adapter
```

审计事件结构属于 framework，审计落库、查询和管理后台属于消费方或后续平台服务。
