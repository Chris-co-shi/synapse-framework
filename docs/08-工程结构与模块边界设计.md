# 23-工程结构与模块边界设计

## 1. 一阶段工程结构

一阶段 Maven reactor 只包含以下模块：

```text
synapse-bom
synapse-core
synapse-webmvc
synapse-data
synapse-cache
synapse-security
synapse-oauth2
synapse-audit
synapse-file
synapse-mq
```

历史目录如果暂时保留，但没有进入 reactor，不视为一阶段模块。

## 2. 通用包结构

模块内部优先使用以下包名表达技术职责：

```text
com.indigo.synapse.<module>
├── autoconfigure
├── properties
├── context
├── exception
├── annotation
├── port
├── adapter
├── propagation
├── support
└── internal / infrastructure
```

不是每个模块都必须拥有所有包。包结构应按实际能力建立，禁止为了形式完整而空建包。

## 3. 包职责说明

- `autoconfigure`：Spring Boot 自动配置。
- `properties`：配置属性。
- `context`：上下文模型、上下文持有与传播。
- `exception`：模块内异常、错误码或异常桥接。
- `annotation`：技术注解，例如权限声明。
- `port`：SPI / Port，只定义接口，不绑定具体基础设施。
- `adapter`：轻量技术适配器。
- `propagation`：跨线程、跨消息、跨请求的上下文传播。
- `support`：通用辅助能力或测试辅助。
- `internal` / `infrastructure`：模块内部实现，不作为主要对外契约。

## 4. 模块边界规则

### 4.1 core

`core` 是最底层模块，不得依赖其他 synapse 技术模块。

允许放入：

- 通用错误码。
- 通用异常。
- OperationContext。
- OperationActor。
- OperationSource。
- 通用 ID / 基础工具。

不允许放入：

- security 场景细分错误码。
- web 响应模型。
- data 插件。
- cache 实现。
- message/file/audit 业务契约。

### 4.2 web

`web` 只做 Servlet MVC 基础能力。

允许放入：

- `Result`。
- MVC 全局异常处理。
- Filter 阶段异常桥接。
- MVC trace 支撑。

不允许放入：

- WebFlux。
- Gateway。
- SecurityFilterChain。
- 业务 Controller。

### 4.3 security

`security` 只做轻量安全上下文和权限检查。

允许放入：

- `AuthenticatedUser`。
- `SecurityContext`。
- trusted-header。
- `PermissionChecker`。
- `@RequirePermission`。

不允许放入：

- Spring Security Web。
- OAuth2 Resource Server 实现。
- 用户中心。
- 角色授权后台。
- ABAC / DataScope。

### 4.4 oauth2

`oauth2` 承载 OAuth2 / JWT / JWK 技术能力，可以依赖 `security`，但不承载业务登录和授权后台。

### 4.5 data

`data` 只做数据层技术基础能力。当前重点是 OperationContext 驱动的自动填充。

不允许依赖 `web`、`security`、`audit`、`message`、`file`、`cache`。

### 4.6 audit

`audit` 只做审计事件契约，不直接依赖 data 落库，不实现审计后台。

### 4.7 mq

`mq` 只做 MQ 契约和 SPI，不做真实 MQ SDK、渠道 SDK、DB Repository。

### 4.8 cache

`cache` 只做缓存基础设施，不写业务 key，不写业务缓存规则。

### 4.9 file

`file` 只做文件存储基础抽象，不做文件中心。

## 5. 禁止结构

生产代码中禁止出现：

- 业务 `Controller`。
- 业务 `Entity`。
- 业务 `Mapper`。
- 业务 `Repository`。
- 生产 `*Application` 启动类。
- 前端工程目录。
- 示例业务应用。
- 与一阶段无关的平台服务实现。

## 6. 注释规则

必须有必要 Javadoc 或注释的对象：

- 公共 SPI / Port。
- 公共 Annotation。
- AutoConfiguration。
- Properties。
- 上下文传播。
- 异常桥接。
- 并发、幂等、限流、锁。
- 安全边界。

注释应说明原因、边界和风险，不重复代码做了什么。

## 7. 测试规则

测试样例也不能暗示业务归属。

避免使用：

```text
order
inventory
warehouse
customer
supplier
employee
avatar
attachment
```

优先使用：

```text
sample
subject
resource
operation
object
item
scope
```

security 模块中的 `role`、`permission` 属于技术安全抽象，可以保留。
