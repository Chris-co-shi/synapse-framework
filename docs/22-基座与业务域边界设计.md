# 22-基座与业务域边界设计

## 1. 总原则

基座负责技术能力，业务域负责业务语义。

## 2. 基座可以拥有

- 技术上下文。
- 技术事件。
- 技术配置。
- 技术 SPI。
- 技术 adapter。
- 技术测试支撑。

## 3. 业务域必须拥有

- 业务模型。
- 业务流程。
- 业务权限码。
- 业务 API。
- 业务表结构。
- 业务前端页面。
- 启动应用。

## 4. 边界检查

任何新增代码前必须回答：

1. 是否出现业务名词？
2. 是否需要业务表？
3. 是否需要业务 Controller？
4. 是否需要启动应用？
5. 是否可以被多个项目复用？

只要依赖具体业务语义，就不得进入 framework。
