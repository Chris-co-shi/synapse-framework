# 02-总体架构设计

## 1. 一阶段架构总览

```text
synapse-framework
├── synapse-bom
├── synapse-core
├── synapse-web
├── synapse-data
├── synapse-cache
├── synapse-security
├── synapse-oauth2
├── synapse-audit
├── synapse-file
└── synapse-mq
```

一阶段只包含技术基座模块，不包含业务系统、平台服务、启动应用和前端工程。

## 2. 模块职责

### synapse-bom

统一管理一阶段模块和第三方依赖版本，供业务项目或内部模块引用。

### synapse-core

框架最底层公共契约，包含：

- `ErrorCode` / `CommonErrorCode`。
- `SynapseException` 及通用认证、授权异常。
- `OperationContext` / `OperationActor` / `OperationSource`。
- ID 生成等基础工具。

### synapse-web

Servlet MVC Web 基础能力，包含：

- 统一 `Result` 响应模型。
- MVC 全局异常处理。
- 常见请求异常到 HTTP 状态码的映射。
- Servlet Filter 阶段 `SynapseException` 桥接。
- Trace 相关基础能力。

`synapse-web` 不包含 WebFlux / Gateway。

### synapse-data

数据层基础设施，当前核心是基于 `OperationContext` 的创建人、更新人等字段自动填充能力。

`synapse-data` 不承载业务表、业务 Mapper 或业务 Repository。

### synapse-cache

缓存基础设施，包含：

- CacheClient / TieredCacheClient。
- Caffeine L1 缓存。
- Redis L2 缓存。
- Redis Lua 执行。
- Redis 可重入锁。
- 滑动窗口限流。
- 幂等 Guard。

缓存 key、锁粒度、限流维度由业务系统决定。

### synapse-security

轻量安全上下文与权限检查基础能力，包含：

- `AuthenticatedUser`。
- `SecurityContext`。
- trusted-header 解析、签名、timestamp 校验。
- `TrustedHeaderAuthenticationFilter`。
- `PermissionChecker`。
- `@RequirePermission` AOP 适配。
- security 与 `OperationContext` 的适配。

`synapse-security` 不引入 Spring Security Web / SecurityFilterChain / MethodSecurity。

### synapse-oauth2

OAuth2 / JWT / JWK 相关技术能力模块。

该模块可以作为 security 技术能力的扩展，但不承担业务登录、用户体系、客户端管理后台等平台职责。

### synapse-audit

审计事件契约模块，包含审计事件模型、审计动作、审计来源等基础定义。

审计落库、审计查询、审计后台属于消费方或后续平台服务。

### synapse-file

文件存储基础抽象模块，包含：

- `FileStorage`。
- `StoreFileCommand`。
- `FileObject`。
- `StoredFile`。
- `LocalFileStorage`。
- 文件模块自动配置。

不包含上传下载 Controller、附件业务表、文件权限、预览、转码、OCR、水印。

### synapse-mq

MQ 消息契约模块，包含：

- 通用消息外壳。
- 消息头约定。
- OperationContext 消息传播。
- 消息发布 SPI。
- 消息消费处理 SPI。
- 消息发布结果。
- 消息消费结果。

不包含 RocketMQ / Kafka / RabbitMQ 真实适配器，不包含钉钉、企业微信、短信、邮件等 SDK 实现，不包含消息中心后台。

## 3. 依赖方向

基础依赖方向：

```text
core
  <- web
  <- data
  <- cache
  <- security
  <- oauth2
  <- audit
  <- file
  <- mq
```

允许：

```text
web      -> core
security -> core
oauth2   -> security / core
data     -> core
cache    -> core
audit    -> core
file     -> core
mq       -> core
```

禁止：

```text
core -> 任何上层技术模块
web -> security
security -> web
data -> security / web / audit / mq / file / cache
audit -> data / security / mq / web
mq -> data / security / audit / cache / file / web
file -> web / data / security / audit / mq
cache -> web / data / security / audit / mq / file
framework -> business application
```

## 4. 设计原则

- 技术能力模块化。
- 公共契约放 core。
- 上下文传播基于 `OperationContext`。
- 业务语义由消费方拥有。
- 自动配置必须允许用户 Bean 覆盖。
- 默认能力必须可关闭或条件装配。
- 一阶段不做平台服务。
- WebFlux / Gateway 后续单独模块处理。
