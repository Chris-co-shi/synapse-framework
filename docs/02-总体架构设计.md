# 02-总体架构设计

## 1. 当前架构总览

```text
synapse-framework
├── synapse-bom
├── synapse-core
├── synapse-webmvc
├── synapse-webflux
├── synapse-cloud
├── synapse-time
├── synapse-config
├── synapse-i18n
├── synapse-data
├── synapse-cache
├── synapse-security
├── synapse-oauth2-core
├── synapse-oauth2-authorization-server-support
├── synapse-oauth2-resource-server-webmvc
├── synapse-oauth2-resource-server-webflux
├── synapse-audit
├── synapse-file
└── synapse-mq
```

当前只包含技术基座模块，不包含业务系统、平台服务、启动应用和前端工程。

## 2. 模块职责

### synapse-bom

统一管理 Framework 内部模块和第三方依赖版本，供业务项目或 Platform 服务引用。

### synapse-core

框架最底层公共契约，包含：

- `ErrorCode` / `CommonErrorCode`。
- `SynapseException` 及通用认证、授权异常。
- `OperationContext` / `OperationActor` / `OperationSource`。
- 上下文快照、传播和恢复契约。
- ID 生成等基础工具。

### synapse-webmvc

Servlet MVC 通用技术能力，包含：

- 统一 `Result` 响应模型。
- MVC 全局异常处理。
- 常见请求异常到 HTTP 状态码的映射。
- Servlet Filter 阶段异常桥接。
- Trace / RequestId 和 OperationContext 恢复。

不包含 WebFlux、Gateway 或 OAuth2 Resource Server。

### synapse-webflux

WebFlux 通用技术能力，包含：

- WebFlux Trace / RequestId。
- Reactor Context 请求上下文。
- OperationContextSnapshot 恢复。
- WebFlux 异常响应适配。

不包含 Gateway 路由、Gateway 鉴权业务、可启动 gateway 或 OAuth2 Resource Server。

### synapse-cloud

Spring Cloud / OpenFeign 服务间调用技术适配，包含 OperationContext Header 编解码、Feign RequestInterceptor 和远程错误解码。

不提供 Gateway、注册中心、配置中心、IAM 或业务鉴权。身份 Token 的转发不得拆成用户、角色或权限 Header。

### synapse-time

时间和时区技术支撑，负责 UTC 时间边界、业务日期与 ZoneId 转换及查询范围解析。

### synapse-config

运行时配置读取和解析抽象，不提供配置中心服务或配置管理后台。

### synapse-i18n

国际化消息解析和资源加载抽象，不提供国际化资源管理中心。

### synapse-data

数据层基础设施，当前核心是基于 `OperationContext` 的创建人、更新人等字段自动填充能力。

不承载业务表、业务 Mapper 或业务 Repository。

### synapse-cache

缓存、分布式锁、限流和幂等基础设施。缓存 key、锁粒度和限流维度由消费方决定。

### synapse-security

Web 无关安全主体与权限检查基础能力，包含：

- `AuthenticatedPrincipal`。
- `AuthenticatedUser`。
- `AuthenticatedClient`。
- `SecurityContext`。
- `PermissionChecker`。
- `@RequirePermission` AOP 适配。
- security 与 `OperationContext` 的单向适配。
- 默认密码编码器。

不解析 HTTP Header，不验证 Token，不提供 Servlet Filter / WebFilter，也不引入 Spring Security Web / SecurityFilterChain。

### synapse-oauth2-core

OAuth2 / JWT 协议无关契约，包含 claim 常量、主体类型、token 类型、validator、denylist Port 和 `BearerTokenProvider`。

### synapse-oauth2-authorization-server-support

提供 JWT 签发、RSAKey、JWKSource、JwtEncoder 等授权服务器侧技术支撑，不实现完整 Authorization Server 或 IAM 业务。

### synapse-oauth2-resource-server-webmvc

提供 Servlet OAuth2 Resource Server 技术适配：

- JwtDecoder 条件装配。
- Token validator。
- JWT 到 `AuthenticatedPrincipal` 映射。
- Spring SecurityContext 到 Synapse SecurityContext 桥接。
- 统一 401/403 响应。

### synapse-oauth2-resource-server-webflux

提供 Reactive OAuth2 Resource Server 技术适配，使用 Reactor Context 承载安全与操作上下文。

### synapse-audit

审计事件契约模块，包含审计事件模型、上下文补齐和输出 Port。

审计落库、查询和后台属于消费方或 Platform。

### synapse-file

文件存储基础抽象和本地轻量实现，不包含上传下载 Controller、附件业务表、文件权限、预览、转码、OCR 或水印。

### synapse-mq

MQ 消息契约模块，包含消息外壳、上下文传播、发布消费 SPI、模板、异常分类和幂等契约。

不绑定具体 Broker SDK，不提供消息中心业务。

## 3. 身份认证架构

唯一身份权威是经过密码学验证的 Bearer Token：

```text
Client
  -> Authorization: Bearer <token>
  -> Gateway optional validation
  -> original Bearer Token forwarded
  -> downstream Resource Server validates independently
  -> JWT claims map to AuthenticatedUser / AuthenticatedClient
  -> Synapse SecurityContext
  -> OperationContext / PermissionChecker
```

固定规则：

- Gateway 验证不能替代下游验证。
- 下游服务校验自己的 issuer、audience、签名、有效期和 token contract。
- 不传播或信任用户、角色、权限等身份 Header。
- 不提供身份 Header 恢复模块。

## 4. 依赖方向

主要依赖关系：

```text
synapse-security                         -> synapse-core
synapse-oauth2-core                      -> protocol-neutral dependencies only
synapse-oauth2-resource-server-webmvc    -> oauth2-core + security + webmvc
synapse-oauth2-resource-server-webflux   -> oauth2-core + security + webflux
synapse-oauth2-authorization-server-support -> oauth2-core
synapse-data / audit / mq                -> synapse-core
synapse-cloud                            -> synapse-core + OpenFeign
```

禁止：

```text
core -> 任何上层技术模块
data / audit / mq -> security
security -> webmvc / webflux / oauth2 resource server
webmvc / webflux -> oauth2 resource server
framework -> business application
```

## 5. 设计原则

- 技术能力模块化。
- 公共契约放在最低合理层级。
- 上下文传播基于 `OperationContext`。
- 安全主体与认证协议分离。
- 通用 Web 能力与 OAuth2 Resource Server 分离。
- 身份只信任经过验证的 Token。
- 业务语义由消费方拥有。
- 自动配置必须允许用户 Bean 覆盖。
- 默认能力必须可关闭或条件装配。
- Framework 不提供可启动平台服务。
