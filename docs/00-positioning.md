# Synapse Framework 项目定位

## 1. 一句话定位

Synapse Framework 是面向企业内部应用的 Java 后台管理框架和快速开发底座。

它不是单一业务系统，也不是简单脚手架，而是为企业内部系统提供统一基础能力的框架。

## 2. 为什么存在

企业内部系统通常反复建设以下能力：

- 登录认证
- 权限控制
- 用户角色菜单
- 组织架构
- 字典配置
- 参数配置
- 操作日志
- 登录日志
- 文件上传
- 数据权限
- 多租户
- 代码生成
- 审计追踪
- 消息通知
- 工作流
- 监控运维

这些能力如果每个项目重复开发，会导致：

- 代码风格不一致
- 权限模型不一致
- 审计不可追踪
- 表结构不统一
- 接口风格不统一
- AI Agent 生成代码不可控
- 后续维护成本高

Synapse Framework 的目标是把这些能力沉淀成统一底座。

## 3. 核心用户

- 企业内部 Java 后端团队
- 需要快速构建后台管理系统的开发者
- 需要统一权限和系统管理的业务平台
- 使用 AI Agent/Codex 协作开发的工程团队

## 4. 第一版边界

Synapse v0.1 只解决：

```text
后台管理框架最小闭环 + AI 可控开发规范
```

包含：

- 统一认证登录
- RBAC 权限
- 用户、角色、菜单、权限
- 字典、参数配置
- 操作日志、登录日志
- 统一异常、响应、错误码
- 统一分页、审计字段
- MyBatis-Plus 持久化规范
- Flyway 数据库版本管理
- 代码生成器最小闭环
- Vue3 管理后台骨架
- Codex/AI 协作规范

## 5. 第一版不做什么

不做：

- 完整低代码平台
- 完整在线表单
- 完整工作流平台
- 完整微服务治理
- 完整 BI 报表平台
- 完整插件市场
- 完整 AI 应用平台
- 具体业务系统，如 MES/WMS/QMS/ERP/CRM

## 6. 长期愿景

长期目标是形成：

```text
Synapse Framework
  -> Synapse Admin
  -> Synapse IAM
  -> Synapse Codegen
  -> Synapse Tenant
  -> Synapse Workflow Adapter
  -> Synapse Business Modules
```

最终可以支撑：

- 企业统一认证权限平台
- 企业统一后台管理平台
- 快速业务应用生成
- 业务模块插件化接入
- 多租户 SaaS 化
- AI Agent 规范化开发

## 7. 设计原则

1. 单体优先，模块化设计。
2. 框架和业务分离。
3. 规则先行，代码后行。
4. 生成代码必须可读、可测、可维护。
5. 技术栈现代化，但不盲目追新。
6. 安全默认开启，权限默认拒绝。
7. 基础能力通用化，业务能力插件化。
8. AI Agent 必须受文档和 Skill 约束。
